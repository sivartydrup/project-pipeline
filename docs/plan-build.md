# Task plan and verified completion evidence

P09 adds a structured plan with epics, tasks, acceptance criteria, weights, verification commands, deliverables, risk, and `blocks`/`informs` dependency edges. Draft plan revisions are immutable snapshots. Owner approval requires the latest brief to be approved, binds to the exact plan revision and SHA-256 hash, then creates a new active scope. Blocking cycles fail validation; tasks with unresolved blockers do not appear in the runnable list. Criterion verification records required evidence references and verifier before an owner can accept a task. Portfolio completion uses only accepted, evidenced weight in the active approved scope.

## Windows plan review journey

On 8 October 2026, the desktop app used a separate temporary profile. In its Plan view I created a **Foundation** epic, a **Build local shell** task, an acceptance criterion, and a verification command. I saved plan revision 1, approved it as scope 1, submitted the task for review, attached a `test-log` reference, verified the criterion, and accepted the task. The portfolio displayed 0% until acceptance, then 100%. Restarting the app retained the accepted task and completion. I also verified that editing the task title keeps its editor expanded; that edit was not saved. The [Windows plan review screenshot](evidence/plan-review-windows.png) shows the approved scope, accepted task, evidence reference, and portfolio completion. The test profile is outside the repository and the owner's normal app data.

## Automated verification and sample export

The [test log](evidence/p09-test.log) covers all four-node blocking-edge combinations against topological sorting, every accepted subset for three sets of task weights, stale revision rejection, audit rollback, blocked scheduling, missing evidence, scope change with accepted-work carry-forward, pending-brief approval denial, v3-to-v4 migration, engine restart, and plan export. The [sample plan export](evidence/sample-plan.json) is generated by `cargo run -p pipeline-store --example sample_plan_export`; it contains a two-task approved graph and one accepted task with evidence.

Windows `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`, and `cargo build -p pipeline-app` passed on 8 October 2026. M1 Max hands-on testing remains a release gate under P19.
